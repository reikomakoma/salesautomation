# 01. 業務フロー棚卸し

営業リスト作成から稼働・運用までの全11ステップを棚卸しする。
各ステップについて「目的 / インプット / アウトプット / 担当 / 使用ツール / 現状の課題」
を整理し、後段の一元管理・自動化設計の土台とする。

---

## フェーズ① リード獲得

### 1. 営業リストを作る
- **目的**: アプローチ対象となる企業リストを用意する
- **インプット**: ターゲット条件（業種・規模・エリア・役職 など）
- **アウトプット**: 企業リスト（会社名 / URL / 問合せフォームURL / 業種 / 規模 / 担当者情報）
- **担当**: 営業／リサーチ担当
- **使用ツール（現状）**: スプレッドシート、リスト作成ツール、スクレイピング
- **課題**: 手作業での収集に時間がかかる。重複・表記ゆれ。フォームURLの抽出漏れ。

### 2. アプローチ戦略を考える
- **目的**: セグメント別に「誰に・どの切り口で・どの文面で」当てるかを決める
- **インプット**: 営業リスト、過去の反応データ、商材の刺さりどころ
- **アウトプット**: セグメント定義、文面テンプレート、優先順位付きリスト
- **担当**: 営業責任者／マーケ
- **使用ツール（現状）**: ドキュメント、スプレッドシート
- **課題**: 戦略と文面がリストに紐づかず属人的。効果測定がしづらい。

### 3. フォーム営業をする
- **目的**: 対象企業の問合せフォームからアプローチ文面を送信する
- **インプット**: 優先順位付きリスト、文面テンプレート
- **アウトプット**: 送信ログ（送信日時 / 到達可否 / 文面バージョン）
- **担当**: 営業／アシスタント
- **使用ツール（現状）**: 手動送信 or フォーム送信ツール
- **課題**: 送信実績がリストに反映されず、二重送信・未送信が発生。返信の受け皿が分散。

---

## フェーズ② 商談・受注

### 4. 文面に記載した Spir 経由で商談が調整される
- **目的**: 相手に日程を選んでもらい、商談を自動でカレンダーに入れる
- **インプット**: 文面内のSpir日程調整URL
- **アウトプット**: 確定した商談予定（Googleカレンダー登録、Web会議URL）
- **担当**: Spir（自動）＋営業
- **使用ツール（現状）**: Spir、Googleカレンダー
- **課題**: アポ確定が「予定表に入るだけ」で、案件レコードとして起票されない。
  誰が・どのリストの企業からのアポか、後追いで手作業紐付け。

### 5. 商談をする
- **目的**: ヒアリング・提案を行い、受注に向けて前進させる
- **インプット**: 商談予定、事前情報、提案資料
- **アウトプット**: 商談メモ、ネクストアクション、確度、想定金額
- **担当**: 営業
- **使用ツール（現状）**: Web会議、メモ、資料
- **課題**: 商談メモがパイプラインに反映されず、次アクションの抜け。

### 6. 商談のステータスをパイプライン管理する
- **目的**: 各商談の進捗（確度）を可視化し、次アクションを管理する
- **インプット**: 商談メモ、確度、金額
- **アウトプット**: 更新されたパイプライン（ステータス／金額／次アクション日）
- **担当**: 営業／営業責任者
- **使用ツール（現状）**: スプレッドシート or CRM
- **標準ステータス例**: `リード → 初回商談 → 提案 → 検討 → 受注 / 失注`
- **課題**: 更新が手動で鮮度が落ちる。滞留案件のアラートがない。

### 7. 受注に上がったらキックオフMTGを設定する
- **目的**: 受注確定と同時に、稼働に向けた最初の会議を押さえる
- **インプット**: 受注ステータス、先方・自社の担当者
- **アウトプット**: キックオフMTG予定、稼働準備フェーズの起票
- **担当**: 営業→カスタマーサクセス（引き継ぎ）
- **使用ツール（現状）**: Spir／カレンダー、メール
- **課題**: 受注→キックオフ→準備の**引き継ぎが手作業**で、担当交代時に情報が落ちる。

---

## フェーズ③ オンボーディング

### 8. 案件のスタート準備をする
- **目的**: 稼働に必要な準備物を揃える
- **サブタスク**:
  - ターゲットの選定
  - 契約書の締結
  - 商材のレクチャー
  - スクリプトの作成
  - 営業リストの作成（案件用）
  - 商談管理シートの作成
- **アウトプット**: 準備物一式（契約書 / スクリプト / リスト / 管理シート）
- **担当**: カスタマーサクセス／運用ディレクター
- **使用ツール（現状）**: Google Drive、スプレッドシート、ドキュメント
- **課題**: 案件ごとに毎回ゼロから作成。テンプレ化・抜け漏れチェックが属人的。

### 9. 準備物スプレッドシートを先方に共有し、双方のタスクを消化する
- **目的**: 稼働開始前の準備タスクを先方と共同で管理・完了させる
- **インプット**: 準備物チェックリスト
- **アウトプット**: 双方タスクの完了、稼働開始のGoサイン
- **担当**: 自社担当＋先方担当
- **使用ツール（現状）**: 共有スプレッドシート
- **課題**: 先方タスクの進捗が見えにくく、リマインドが手動。準備完了の判定が曖昧。

---

## フェーズ④ 稼働・運用

### 10. 稼働開始
- **目的**: 準備完了を受けて実運用を開始する
- **インプット**: 完了した準備物、稼働開始日
- **アウトプット**: 稼働中案件（KPIトラッキング開始）
- **担当**: 運用チーム
- **課題**: 稼働開始のトリガーで定例MTGやレポート体制が自動で立ち上がらない。

### 11. 運用・改善サイクル（← 空欄だったステップを補完）
- **目的**: 稼働案件のパフォーマンスを可視化し、継続的に改善・拡大する
- **サブタスク（提案）**:
  - 定例MTGの実施（週次／月次）
  - KPIモニタリング（架電数 / アポ数 / 商談数 / 受注数 / 稼働リードタイム）
  - レポーティング（先方共有用の定期レポート）
  - 改善アクション（スクリプト・リスト・戦略の改善）
  - 継続・追加提案（契約更新 / アップセル / 追加案件）
- **アウトプット**: 定期レポート、改善施策、更新／追加受注
- **担当**: 運用チーム／カスタマーサクセス
- **課題**: レポート作成が手作業。改善が案件横断でナレッジ化されない。

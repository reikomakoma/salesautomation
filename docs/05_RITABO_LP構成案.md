## 1. LPの前提整理

| 項目 | 内容 |
| --- | --- |
| サービス | RITABO（営業代行）|
| 提供範囲 | リード獲得（リスト作成〜フォーム営業）→ アポ獲得 → 商談 → 受注 → オンボーディング → 稼働・運用改善までの一気通貫（資料の11ステップに対応）|
| 想定ターゲット | 営業リソース・ノウハウが不足している企業。<br>・新規開拓をしたいが営業専任がいない中小企業／スタートアップ<br>・アポは取れるが商談〜受注〜稼働の管理が回っていない企業 |
| ターゲットの検討状況 | 「営業代行 比較検討中」「テレアポ代行で失敗した経験あり」層を主に想定。丸投げしたいが"ブラックボックスな代行"に不信感がある層に刺す |
| LPのゴール（CV） | **無料相談（オンライン30分）の予約** を第一CV。Spirの日程調整URL直結で、フォーム入力→日程確定まで離脱させない（自社サービスでも使っている仕組みをCV導線でそのまま見せる）|
| サブCV | 資料ダウンロード（サービス概要・料金表）※検討初期層の受け皿 |

## 2. 訴求の軸と優先順位（資料ベースで言語化）

資料から導いたRITABOの強みを、LPで押し出す順に並べる。

### 優先度A（メイン訴求・ファーストビューで言う）

1. **「アポ獲得だけ」で終わらない、受注・稼働まで伴走する一気通貫の営業代行**
   - 根拠: 資料の11ステップ（リスト作成→フォーム営業→アポ→商談→受注→オンボーディング→稼働・運用改善）を自社の標準プロセスとして持っている
   - 言語化例: 「リスト作成から受注後の立ち上げまで。営業の"全工程"を代行します」
2. **プロセスと数字が全部見える、ブラックボックスにしない営業代行**
   - 根拠: 案件IDで全工程を貫く一元管理設計＋KPI定義（送信数／アポ数・率／商談数／受注数・率／稼働リードタイム／継続率）
   - 言語化例: 「送信数からアポ率・受注率まで、すべての数字を毎週レポート。何をやっているか見えない代行にしません」

### 優先度B（サブ訴求・中盤セクションで補強）

3. **受注後の立ち上がりが速い（稼働リードタイムを管理指標にしている）**
   - 根拠: 受注→キックオフ→準備物チェックリスト→稼働開始までをテンプレ化・自動化し、「稼働リードタイム」をKPIとして計測
   - 言語化例: 「ご契約後、キックオフ〜稼働開始までの日数もKPI管理。『契約したのに始まらない』を防ぎます」
4. **仕組み化された効率的なアポ獲得（フォーム営業 × Spir自動日程調整）**
   - 根拠: セグメント設計→文面テンプレート→フォーム送信→Spirで日程自動確定、送信ログ・反応データを蓄積して文面を改善するサイクル
   - 言語化例: 「送りっぱなしにしない。文面バージョンごとの反応を計測し、勝ちパターンに寄せていきます」

### 優先度C（信頼補強・後半セクションで言う）

5. **改善サイクルが標準装備（週次定例・KPIモニタリング・スクリプト/リスト改善）**
   - 根拠: ステップ11「運用・改善サイクル」（定例MTG／KPIモニタリング／レポーティング／改善アクション）
6. **引き継ぎ・抜け漏れが起きない運用体制**
   - 根拠: 営業→CSの引き継ぎ、準備物チェックリスト、双方タスク管理を仕組みとして持っている（属人化への課題意識が資料全体を貫いている）

> メモ: 競合の営業代行LPは「アポ獲得数」訴求が多い。RITABOは資料上プロセス管理・透明性・受注後まで含めた設計が最大の差別化ポイントなので、A-1「一気通貫」＋A-2「見える化」の2枚看板で行く。

## 3. LPセクション構成（上から順）

### ① ファーストビュー（FV）
- **キャッチコピー案**（A訴求）:
  - 「営業リスト作成から、受注後の稼働まで。"全工程"を代行する営業代行 RITABO」
  - 「アポを取って終わり、にしない。数字が全部見える営業代行」
- サブコピー: 対象（営業リソース不足の企業）＋提供価値（一気通貫・見える化）を1文で
- CTAボタン: 「無料相談を予約する（30分・オンライン）」（Spir直結）
- 補助要素: 実績数値を3つ横並び（例: 累計送信数／平均アポ率／継続率）※数値は要確認
- ビジュアル: 11ステップの流れ or KPIダッシュボードのイメージ

### ② 課題共感（こんなお悩みありませんか）
資料の「現状課題」をそのまま顧客の悩みに翻訳して3〜4個:
- 「新規開拓をしたいが、リスト作成やアプローチに手が回らない」
- 「営業代行に頼んだが、何をやっているか見えず成果も不明だった」
- 「アポは取れるが、その後の商談管理・受注後の立ち上げがぐちゃぐちゃ」
- 「営業の数字（アポ率・受注率）が把握できず、改善のしようがない」

### ③ 解決策の提示（RITABOとは）
- 「その課題、営業プロセスまるごとの代行で解決します」
- 11ステップ図（README のフロー図を簡略化した4フェーズ: リード獲得→商談・受注→オンボーディング→稼働・運用）を掲載
- ここで A-1（一気通貫）を明言

### ④ 選ばれる理由（強み3つ）
1. **全工程ワンストップ**（A-1）— リスト作成〜稼働後の改善まで
2. **完全見える化**（A-2）— 案件ごとの進捗とKPIを常時共有・毎週レポート
3. **スピード立ち上げ**（B-3）— テンプレ化された準備プロセスで契約後すぐ稼働
※各カードに根拠となる仕組み（一元管理・KPI定義・準備物チェックリスト）を1行添える

### ⑤ サービスの流れ（ご契約後のステップ）
資料の11ステップを顧客視点の5ステップに圧縮:
1. 無料相談・ヒアリング（ターゲット・商材の確認）
2. 戦略設計（セグメント定義・文面/スクリプト作成・リスト作成）
3. アプローチ開始（フォーム営業→Spirで自動日程調整）
4. 商談・受注（パイプライン共有・毎週レポート）
5. 運用・改善（週次定例・KPIレビュー・文面/リスト改善）
- 各ステップに「お客様にやっていただくこと」を明記（準備物シートの双方タスク管理を透明性の証拠として見せる）

### ⑥ 見える化の具体（レポーティング）
- KPIレポートのサンプル画像（送信数→アポ率→商談数→受注率のファネル）
- 「毎週この形で数字をご報告します」＋管理画面（案件一元管理）のスクリーンショット
- B-4のフォーム営業改善サイクル（文面バージョン別の反応計測）もここで言及

### ⑦ 料金プラン
- ※要確定。想定: 月額固定 or 固定＋成果報酬のハイブリッド、2〜3プラン
- 「何にいくらかかるか」を明示すること自体が透明性訴求と一貫する
- 最低契約期間・初期費用の有無も明記

### ⑧ 実績・お客様の声
- ※実績データ・事例の有無を要確認。無い場合は「支援領域・体制」の紹介に差し替え
- 事例フォーマット: 業種／課題→施策→数値成果（アポ率・受注数・稼働までの日数）

### ⑨ よくある質問（FAQ）
- 「どんな業種・商材に対応できますか」
- 「最低契約期間はありますか」
- 「アポ獲得だけの依頼もできますか」（→一気通貫が基本だが柔軟対応、と回答）
- 「成果はどのように報告されますか」（→⑥へ誘導）
- 「契約から稼働開始までどのくらいかかりますか」（→B-3訴求の再掲）

### ⑩ クロージングCTA
- コピー: 「まずは現状の営業課題をお聞かせください」
- CTAボタン（Spir直結の無料相談予約）＋サブCTA（資料ダウンロード）
- 追伸的な一言で「無理な営業はしません」等の心理障壁の除去

### ⑪ フッター
- 運営会社情報／特商法・プライバシーポリシー／お問い合わせ

## 4. CV導線・その他メモ

- **CTA配置**: FV直下・④の後・⑥の後・⑩の計4箇所。すべて同一文言で統一
- **フォーム**: 入力項目は最小限（会社名・氏名・メール）→送信後Spirで日程確定。
  自社の「アポ調整自動化」をCV導線で体験してもらう構成にする
- **スマホ最適化前提**: 比較検討層は移動中閲覧が多い想定。11ステップ図はスマホでは縦積みに
- **トーン**: 誠実・ロジカル。「爆増」「圧倒的」系の煽り文言は透明性訴求と矛盾するので使わない

## 5. 制作前に確定が必要な項目（要確認リスト）

1. 実績数値（累計送信数・平均アポ率・受注実績・継続率）→ FV・⑧に必要
2. 料金体系（固定/成果報酬、プラン数、初期費用、最低契約期間）→ ⑦に必要
3. 掲載可能な事例・お客様の声の有無 → ⑧の構成が変わる
4. 対応可能な業種・商材の範囲（絞るか広く取るか）→ ②⑨の書き方が変わる
5. 会社情報・特商法表記 → ⑪に必要
6. サブCVの資料（サービス概要資料）の有無 → 無ければ第一CV一本に絞る
